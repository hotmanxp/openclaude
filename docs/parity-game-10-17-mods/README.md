## 2. 比赛范围

### 2.1 在范围内

MOD 子系统的**基础模块实现**与**接线点**，二者都算：

- **基础模块实现** = `src/mods/` 下的协议、事件表、dispatch、tier 链、matcher、loader、沙箱、`$` 能力面、插件配置、UI 元素表、渲染链
- **接线点** = 宿主代码里所有调用 mods dispatch 的位置，以及**该有而没有**的位置（`src/` 全仓扫，不限于 `src/mods/`）

### 2.2 不在范围内

- 内建插件的业务逻辑本身（`src/mods/builtin/diff/` 等的 diff 算法、handoff 逻辑）——除非它暴露了**能力面缺口**
- MCP 服务端协议本身的完整性
- 非 MOD 的其它子系统（工具层、模型层、provider 等）——留给后续场次
- 代码风格、命名、注释质量

### 2.3 环节一必答的 12 个维度（考纲）

**这是本赛唯一的公开考纲。12 个维度全部真实存在于 2.1.302，裁判已逐项验证过它们在 d.ts 或 bundle 中有实体。** 每个维度都要给一份勘定结论，**给不出也要写"我查了哪里、为什么给不出"**。

| # | 维度 | 至少要回答 |
|:-:|---|---|
| 1 | 事件注册表 | 事件名的完整清单与分组方式；每组的判别标准 |
| 2 | `$` 能力面 | 全部 noun 名与每个 noun 的方法签名 |
| 3 | 事件载荷与守卫 | 载荷形状；参数/结果合法性检查与「非法改动回落到上一个合法值」这一层是否存在、长什么样 |
| 4 | tier 链 | 层序、各层可下钻范围、`next.to` 的语义与限制 |
| 5 | matcher 形状 | 允许的写法、叶子类型、深度上限、`to` 的唯一性约束 |
| 6 | hook 生命周期语义 | 失败如何处理、载荷如何冻结、有哪几个时钟常量及其**确切含义** |
| 7 | 加载与沙箱 | 静态扫描是拒斥式还是提取式、Transpiler、Worker / vm realm 层级、体积限制 |
| 8 | 插件清单与配置 | 清单字段、`ConfigKind` 的取值、picker 渲染规则、敏感值存储 |
| 9 | UI 渲染面 | 有哪几个 surface、每个 surface 的元素表、有哪些组件是某几个 surface 专有 |
| 10 | 内建插件集合 | 插件名单与各自的加载条件 |
| 11 | 名词扩展机制 | 插件如何给 `$` 增加 noun（哪个事件、什么语义） |
| 12 | 流式 dispatch | 是否存在流式派发形态，与同步形态的关系 |

## 3. 铁律（违反即判违规）

1. **只读源码。** 禁止对 `src/`、`scripts/`、`web/`、`package.json`、`tsconfig.json`、以及 `docs/` 下任何既有文件做 Edit/Write/删除。**包括 `docs/mods-*.md`——看到里面有错也不许改**，写进你的勘误节交给裁判（见 §5.6）。
2. **禁止改动 git 状态。** 不得 `commit` / `add` / `stash` / `reset` / `checkout` / `restore` / `clean` / `push` / `rebase`，不得改 `git config`，不得建分支或 worktree。
3. **唯一允许写入仓库的位置**是你自己的三份文档：`surface-<你的名字>.md`、`gaps-<你的名字>.md`、`crosscheck-<你的名字>.md`。名字只能取 `opencc` 或 `claude`。
4. **临时文件只进 `/tmp`。** 探针、脚本、快照一律写 `/tmp/parity-<你的名字>/`（自己 `mkdir -p`）。**禁止**把临时脚本写进仓库任何目录再删。
5. **禁止删除或篡改他人文档。**
6. **环节一、二期间禁止阅读对方的三份文档。** 你的判断必须独立形成。这是本赛制最容易被自我污染的一条。
7. **禁止编造。** 没有验证过的东西不许写成"已核实"。不确定就降证据等级（§5.4）写"未验证"——这不丢人，编造才丢人。
8. **禁止 `bun test` 全量。** 只能跑单文件/指定文件，且必须重定向到日志文件再读（见 [`EVIDENCE.md`](./EVIDENCE.md) §四）。
9. **禁止用 tmux 驱动 TUI。** 用户线上会话跑在 tmux 里，新建或杀 session 属于动共享状态。

违规扣分见 §9。

## 4. 环节一 · 上游能力面勘定

**目标**：不看 opencc，先把「上游有什么」这件事独立搞清楚。范围是 §2.3 的 12 个维度。

### 4.1 交付物

`docs/parity-game-10-17-mods/surface-<你的名字>.md`，结构见 [`TEMPLATE-surface.md`](./TEMPLATE-surface.md)。

### 4.2 硬性要求

- **每个维度都要有上游坐标。** 坐标形式：`d.ts:行号` 或 `bundle.js@字节偏移` 或 `modules/<文件>:<行>`。**只写结论不给坐标的维度记 0 分。**
- **另需一节：2.1.296 → 2.1.302 的 MOD 面 delta。** 两份 d.ts 都在（§1.1），diff 是机械工作。真实追平必须先知道这层变化，否则会把「上游新增」误判成「一直缺」或反之。**这一节单独计分（见 §8）。**
- **如实写"没查到"。** 「我搜了 bundle 的哪几处、按什么特征串搜的、为什么判定不存在」比一个没有坐标的断言值钱得多。

## 5. 环节二 · 差距清单

**目标**：拿环节一的能力面去对 opencc，产出「要追平得做什么」。

### 5.1 交付物

`docs/parity-game-10-17-mods/gaps-<你的名字>.md`，结构见 [`TEMPLATE-gaps.md`](./TEMPLATE-gaps.md)。

### 5.2 差距分类（每条必归一类）

| 类别 | 含义 |
|---|---|
| `M-MISSING` | 上游有，opencc **完全没有** |
| `M-PARTIAL` | 上游有，opencc 有但不完整 / 只覆盖一部分场景 |
| `M-DEADWIRE` | opencc **声明注册了但没有 dispatch 点**（注册成功、触发不了），或反过来 |
| `M-SEMANTIC` | 两边都有，但**行为或契约不同**（这一类最容易漏，也最贵） |
| `M-SAFETY` | 上游有防线，opencc 无 / 弱 |
| `N-NOT-NEEDED` | 上游有，但 opencc **架构上不需要**——必须论证，论证不出来就按 `M-MISSING` 算 |

> **`N-NOT-NEEDED` 是给"我知道有差距但我认为不该追"的出口。** 静默不写是违规的——那等于把判断藏起来。写出来并论证，才算是一个可被裁判复核的主张。

### 5.3 每条必须给**双侧坐标**

- **上游侧**：`d.ts:行号` 或 `bundle.js@偏移` 或 `modules/<文件>:<行>`
- **下游侧**：`src/...:行号`（若主张"完全没有"，见 §5.5）

只有一侧坐标的条目按 V1 计。

### 5.4 证据等级

| 等级 | 含义 | 判定标准 |
|---|---|---|
| **V3 双侧可执行** | 两侧各跑一次，输出可复现 | 文档里给出**完整命令与真实输出**。上游侧若能在真 2.1.302 二进制上跑（见 [`EVIDENCE.md`](./EVIDENCE.md) §三），优先这么做 |
| **V2 双侧静态可证** | 双侧坐标都精确，且能说清"为什么这一行证明存在/不存在" | 无"可能/大概"式跳跃 |
| **V1 单侧可证** | 只核到一侧，另一侧是推断 | 必须写明缺哪一侧 |
| **V0 仅推测** | 读代码感觉不对 | **不计分**。写进"自我否定清单"即可 |

> 产生大量 V0 是正常的，不要塞进正式清单占位。

### 5.4.1 V3 拆分：对照组要求（硬性）

每条 V3 证据必须包含一个**对照组**，证明「**如果没有这个差距，输出会不同**」。

- **对照组自己先跑一遍、贴输出。** 如果对照组输出与实验组相同，**它没有区分力，等于没做**。
- **探针用到模块级缓存 / 单例 / 全局状态时，每次对照前必须显式复位**，并在脚本里写明复位的调用。
- 常见翻车：用 `toUpperCase` 这类**幂等操作**做对照——它跑两遍结果一样，对照组天然无效；模块级 LRU 还可能让第二次 `cache.get()` 命中陈旧条目，那段"对照"什么都没对照。
- **这条对裁判同样适用**：裁判的裁定脚本也要有对照组。

> 依据：上一届光"探针必须有有效对照组"这一条，就消耗了 3 次选手自查翻车 + 3 次裁判自查翻车。
> **探针骗自己不是理论风险，是每个写探针的人都会踩的**——包括裁判。

### 5.5 「opencc 没有 X」必须自证（本场最重要的一条）

**"不存在"是一个负向断言**，必须附依据：

- 全仓搜索范围（你搜了哪些目录、什么模式、是否剥掉了注释）
- 或构造点枚举（列出每一处 `new Xxx()` / 注册点，说明是否可达）
- 或一个能覆盖未来创建的守卫测试

**无法自证的，证据等级按 V1 计。**

> 依据：`grep` 不到不等于不存在——可能经字符串拼接、动态注册或外部输入构造。**同理，grep 到也不等于接线了**——名字出现在注释、字符串、测试夹具里都不是 dispatch 点（见 [`EVIDENCE.md`](./EVIDENCE.md) §二）。

### 5.6 质量红线

- **不得把现成文档当结论引用。** `docs/mods-upstream-*.md` 可以读，但**每一条引用都必须独立复核**，并在文档里注明「我复核过 / 我复核后修正为 X」。理由见 [`EVIDENCE.md`](./EVIDENCE.md) §五。
- **不得凑数。** 同一根因的多个表现算**一条**。
- **不得把「上游有但 opencc 不需要」伪装成缺口**（也不得反过来）。
- **不得建议修改上游行为。** 本场只追平，不改上游语义。
- **质量优先于数量。** 10 条 V3 的价值远高于 50 条 V1。

### 5.7 时间预算

**约 40 分钟。** 裁判统一叫停。叫停后停止一切新的源码探索，10 分钟内交卷。

## 6. 环节三 · 交叉证伪

环节二收口后开放。读**对方**的三份文档，逐条裁决。

### 6.1 交付物

`docs/parity-game-10-17-mods/crosscheck-<你的名字>.md`，结构见 [`TEMPLATE-crosscheck.md`](./TEMPLATE-crosscheck.md)。

### 6.2 裁决枚举（对对方每一条差距都判）

| 裁决 | 含义 | 你的理由必须包含 |
|---|---|---|
| `CONFIRMED` | 差距真实存在 | 你在源码里核到的双侧 `file:line` + 成立的理由 |
| `PARTIAL` | 差距真实但对方说错了类别/范围/档位 | 错在哪，应该怎么改写 |
| `REJECTED` | 差距不存在或不构成差距 | **具体指出对方推理的哪一步断了**，不能只说"我看不出来" |
| `NOT-ENOUGH-EVIDENCE` | 可能真，但证据不足以支撑其类别或档位 | 还缺什么证据 |
| `IMPLAUSIBLE` | 上游坐标本身可疑（例如引到一个不相关的地方） | 你核到的正确坐标 |
| `DUPLICATE` | 与对方自己的另一条是同一处 | 标注 `DUPLICATE-OF: <对方 ID>` |

> **你的裁决必须落在源码上，不能只落在对方文档上。** 至少要 `Read` 到每一处被引用的坐标。裁判会抽查。

### 6.3 抽验要求（硬性）

对判为 `CONFIRMED`/`REJECTED` 的条目，**至少抽 3 条**（跨不同档位）**亲手复验**，单列 `## 抽验记录` 一节。

### 6.4 主动补充（硬性）

单列 `## 评审中额外发现`：对方漏报、但你抓到了的差距。**至少 1 条**（真有就多写，没有就写"未发现额外发现"并列出你实际看过的地方）。

**这一节不是可选礼貌。** 只会复读别人清单的人，这一节必然是空的。

### 6.5 评审质量红线

- 不得因为"我觉得不可能"就 `REJECTED`——必须指出推理断点。
- **误杀真差距（裁判终裁 `CONFIRMED` 而你判 `REJECTED`）是本环节最严重的错误**，单独扣分（§8）。
- 也不得用 `PARTIAL` 逃避思考。

## 8. 计分公式（满分 100）

### 8.1 勘定分 20

| 项 | 分值 | 规则 |
|---|:-:|---|
| 12 个维度 | 18 | 每维度 1.5 分：结论 + 可核坐标。**无坐标记 0** |
| 296→302 delta 节 | 2 | 完整且双侧可核 |

扣分：裁判抽查 5 处坐标，**核错一处 −0.5**。

### 8.2 差集分 55

```
单条得分 = 档位 D × 证据系数 E

档位 D（对「追平」的阻塞度，由裁判终定）:
  D1 = 8   上游核心机制缺失，且官方内建插件的主路径依赖它
  D2 = 5   能力缺失，但不是任何内建插件的主路径
  D3 = 3   部分实现 / 语义分歧 / 接线缺失
  D4 = 1   边界、次要、或 `N-NOT-NEEDED` 成立但有残留收敛项

证据系数 E:  V3 = 1.0    V2 = 0.8    V1 = 0.4    V0 = 0

差集分 = Σ(有效条目得分)，上限 55
```

量级参考（据此自测产出处在什么水位）：

| 典型产出 | 算式 | 差集分 |
|---|---|---|
| 4 条 D3/V2 | 3×0.8 ×4 | 9.6 |
| 6 条 D2/V2 + 2 条 D3/V3 | 24 + 6 | 30 |
| 2 条 D1/V3 + 4 条 D2/V2 + 3 条 D3/V3 | 16 + 16 + 9 | 41 |
| 3 条 D1/V3 + 6 条 D2/V3 + 4 条 D3/V2 | 24 + 30 + 9.6 | 打满 55 |

**罚则（本场重点）**：

| 情形 | 处罚 |
|---|---|
| **假缺口**（裁判终裁 `REJECTED`，即上游根本没有这个能力 / opencc 其实有） | **−4 / 条**；累计 ≥3 条 → **差集分清零** |
| **假对齐**（你声称"已对齐"，裁判核为 `M-MISSING` / `M-PARTIAL`） | **−4 / 条** |
| 严重度虚报（真差距但档位报高一档以上） | 按低档位计分，额外 **−3 / 条** |
| 正式清单区 V0 占比 > 50% | 记"低证据密度"，**互证分 −5** |

> 漏报**不扣分**。理由见 §7.2：漏报在环节二不可发现，罚一个不可发现的行为等于制造运气分。**假缺口之所以重罚，是因为它会直接污染后续的实施排期**——有人会照着它去改一天代码。

### 8.3 互证分 25

| 项 | 分值 | 规则 |
|---|:-:|---|
| 裁决正确率 | 12 | 与裁判终裁一致得分；不一致 −1/条 |
| 抽验质量 | 8 | 抽验条目中"复验结论与事实一致"的比例 × 8；未做抽验直接 0 |
| 主动补充 | 5 | 按对方漏报条目的档位折算：`D1=2.5, D2=1.5, D3=1, D4=0.5`（以裁判复核为准） |
| 误杀真差距 | 扣分项 | 每条 **−3**（已在正确率之外单独计） |
| 行号核实 | 扣分项 | 裁判抽查 3 处你的引用，核错一处 **−2** |

### 8.4 同分裁决

1. 有效 `D1+D2` 条数多者胜
2. 互证误判少者胜
3. 仍并列：裁判依证据组织质量与覆盖度审计表现主观判定，并在 GAP-LEDGER 说明理由

## 12. 给选手的临门一脚

三句话，来自上两届真实的判错代价：

1. **「grep 到名字」不等于「接上线了」。** 注释、字符串字面量、测试夹具、类型定义全都不算 dispatch 点。裁判自己在这件事上栽过一次——同一个脚本两次跑出的两个数字差了一整个数量级，而**两次看起来都是对的**。**你的"已对齐"结论必须落在真正的调用点上。**

2. **「我证明了入口 A 不存在」不等于「这条能力不存在」。** 可达性论证必须穷尽全部调用方——编译期折叠掉的路径、运行时环境变量闸门、动态注册，都会让 grep 说谎。这条裁判也判错过一次。

3. **照抄现成文档是最省事也最贵的路。** `docs/mods-upstream-*.md` 里的结论**已经被自己推翻过**——同一份文档里既有"24 个 noun"（错的）也有"19 个"（对的），还有一条自标"存疑，可能是自创"。**引用它不加分，独立复核才算数。**

**不要为了赢而堆 V0。** 一条被裁判亲自核实为真的 D1，比二十条看起来很专业的猜测值钱得多——而猜错还要倒扣 4 分。
